Any Ace:ers in this group?

As cool as the Aces decompiler is with its iconic LIST/EDIT/REDEFINE and the ability to concatenate dictionaries upon tape load I remember some odd 40 years ago that over time a larger project could deteriorate. There is no "proof" that the REDEFINE util is buggy it might as well have been a stray C! going somewhere creating a ticking time bomb. When the dangling or un-earthed dictionary pointers hit the fan this would send 17-yo me into orbit. There was simply no sane way to rescue the project. Even though most of the code would LIST just fine you were stuck in a dead end.

Lacking the "screen" utilities or similar to bootstrap the whole system again, the fact that I got a 4x4 block as a working prompt from the 8K ROM only helped so much.

Also when my "Porcupine" i.e. the re-wired 16K Zx81 ram was properly fitted there would have been room to run a more standard approach with screens or even a more advanced line break oriented editor instead of the Ace standard tools.

As cool as the modern day tools such as Hakkinens lua code to generate runnable code are, they is more suited for running the Ace as a kind of "Arduino" producing really cool demos and not for purists wanting to operate inside the ace machine. My findings might also have some interest for the Collapse community.

I hijacked the input buffer in a way that I did not think was possible and had a lot of help coding from AI saving a heap of time. ( Well yeah I know AI is not really being an 80s purist...)

There is a short routine "b0" written in assembler ( it could just as well have been in Forth but I wanted something that could be deployed repeatedly into the ace by hand if needed and not be relying on the binary dictionary save routines)

The "b0" file also has a helper i.e. ": b b0 call ; immediate" which makes this clockwork orange tick.

The second tap file contains the "tine" ( Tine Is Not Emacs) tap file which implements a terrible and buggy mini screen editor for the ace's 32x23 char screen

The assembler code types out a line at a time ending it with " b" and since the Ace input routine is rather naive it will check the stuff typed into the buffer upon return and go: "Wow really, there is still stuff in here and I was so certain I finished, oh well..?" execute the b and the clock goes on till a single "eof" ( ascii NULL char) is encountered.
 
Basically what I tried to re-invent would be the redirect input i.e. "COMPILE < text_input.fs"

Creating a reverse time-capsule ( if there is such a thing) adding a description on how to deploy it, I am now sending it back in a time machine to the mid-eighties.

I successfully ran this on the "EightyOne" emulator in Ace mode but have not tried it on a real machine ( mine went into the bin in the mists of the 90s) also I did not yet try it on the replica.

The first "b0" tap files also work on the online "Jupiteraceemulator.com" though one has to find the rom file oneself. The second tap file "tine" has some issues on the online emulator that i am unable to wrap my head around ( one identical tap file producing differing results on two emulators)

If I get some more inspiration I will intend to store ( ! one simply does not "POKE" the memory in Forth) some creative routine into the "EXWRCH" system variable thus creating an output redirect to save a stuck program via something like an ancient "LIST pgm > somewhere_safe.fs"
